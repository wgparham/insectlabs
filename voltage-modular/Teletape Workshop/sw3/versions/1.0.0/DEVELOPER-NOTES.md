# SW3 Developer Notes — 1.0.0

SW3 is a Teletape Workshop dual CV/manual switching utility. The approved self-contained Java and Designer pair is archived in this version folder. The [user manual](USER-MANUAL.md) documents panel operation; the [release review](REVIEW.md) and [validation harness](tests/validate.py) document implementation checks.

The processing implementation lives in `sw3.java` in `ProcessSample()`, `ProcessBypassedSample()`, the private `Sw3Core`, and `Sw3Core.Gate`. It is a native-rate, allocation-free utility. The SDK-independent core is also archived at [Sw3Core.java](../../../../../switch-primitives/src/com/insectlabs/switches/Sw3Core.java); released SW3 remains self-contained, and validation checks exact source parity.

Preserve the two distinct route layouts: X selects input X1 or X2 into output X; Y sends input Y to output Y1 or Y2. An unpatched X1 or Y input is normalled to its ±10 V reference trimmer in active operation; an unpatched X2 is 0 V. The manual gate and external gate are OR-combined for gate output, while MOMENTARY route selection uses their XOR. LATCH toggles on either rising edge. The external gate uses a 3.0 V rising and 1.8 V falling Schmitt threshold. Gate outputs are 10 V while a gate/button is active and are extended to a minimum 5 ms on a rising edge. Lamps indicate active secondary selection or gate-output activity.

The shared FADE control is exponential from 0 ms (hard switch) to 200 ms at 48 kHz. `FADE_RATIO` is the approved mapping constant; the fade arithmetic is per-sample and allocates nothing. Typed tooltip values are converted through `EditComponentValue()`. X and Y latch orientations differ because the Y side of the panel is rotated. Preserve `X_LATCH_IS_STATE_0` and `Y_LATCH_IS_STATE_0` with the saved switch defaults.

Host bypass copies connected X1 to X, connected Y to Y1, and sends 0 V to Y2 and both gate outputs. It does not read the reference-trim controls or advance fade/gate histories; unpatched primary jacks therefore produce 0 V while bypassed, unlike active normalled operation. The two stored latch states survive bypass, and the first active sample re-primes inputs without synthesizing a new gate edge. This is deliberate and covered by the core checks. There is no separate DSP benchmark; the core is small, uses no process-time allocations, and costs one fixed set of scalar arithmetic operations per sample.

The module's visible Designer Notes field is the exact version marker `v1.0.0`; the earlier scratch design notes were moved into the manual, release review, and developer notes. Re-run the release validation after changing either source form, gate thresholds or polarity, switch orientation/defaults, route normalization, pulse length, FADE mapping, bypass routing, or state restoration.
