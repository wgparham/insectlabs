# FPA developer notes — 1.0.0

This is the immutable 1.0.0 snapshot. Current module notes are maintained at [../../DEVELOPER-NOTES.md](../../DEVELOPER-NOTES.md). The exact canonical source pair is `fpa.java` / `fpa.vmod` in this folder, class `fpa`, package `com.insectlabs.fpa`; the panel render is `fpa_hero.png`. User instructions are in [USER-MANUAL.md](USER-MANUAL.md), release details in [RELEASE-NOTES.md](RELEASE-NOTES.md), and evidence in [REVIEW.md](REVIEW.md) and [VALIDATION.txt](VALIDATION.txt).

FPA has four independent mono preamp/overdrive lanes: C, Re, D and O. Gain is 0–1 (default 0); Tone is −1..+1 (default 0); the four-state selector maps positions 0/1/2/3 to O/D/Re/C, with shipped defaults assigning C/Re/D/O to lanes 1–4. C/Re/D tone center is neutral; O is a low-pass voice whose signed sweep maps logarithmically from 1.5 to 8 kHz. Phase toggles default to normal. Mix is half the sum of the lane outputs. Input and output reference is 5 V per internal DSP unit; lane processing clamps to ±10 V. Host bypass routes each lane directly and silences Mix, then resets core histories on resume.

The DSP uses 2× 23-tap windowed-sinc oversampling around the nonlinear stages, a 12 Hz DC blocker, mode-specific tone, calibration tables, a ±10 V soft ceiling, a 5 ms voicing fade and 4 ms polarity glide. It allocates no objects in the per-sample path. The core assumes 48 kHz and has not been validated at other host rates. Approximate algorithmic latency is 11 samples (0.23 ms at 48 kHz). Construction computes gain calibration tables. The modes are inspired by CE-1, RE-201/301, BD-2 and SD-1 circuits; they do not claim exact electrical reproduction. See [design research](../../references/FPA-Design-Research.md) for evidence labels, references and unresolved questions.

Validation compiles exported and embedded Java against the installed Voltage SDK with Java 17 target, strict lint and warnings as errors. It checks source pairing, Designer binary round-trip, human-readable label display names, Tone metadata and unique control UUIDs, then extracts the exact nested core to run headless tests for calibration, endpoints, ceiling, silence, non-finite inputs, polarity, tone, channel independence and mix scaling. The user confirmed native Designer operation before the authorized tone-only correction; no separate post-correction host audition or native CPU benchmark is recorded. Review limits are documented in [REVIEW.md](REVIEW.md).

Repeat tone center/endpoints if changing tone mapping. Recheck full gain calibration, switch mapping, channel isolation and bypass/resume after changes to core, controls or lifecycle code. Recheck spectral aliasing, latency and native CPU if changing oversampling or nonlinear stages.
